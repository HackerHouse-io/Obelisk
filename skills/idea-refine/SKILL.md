# idea-refine

Turn a one-line feature request into a sharp, testable description.

## Operating rules
- Read the issue, the linked discussion, the README, and any related code.
- Write down what the user actually wants in one paragraph.
- Surface the implicit assumptions: who is the user, what's the input, what's the success criterion.
- List the open questions explicitly. If any are blocking, STOP and ask.

## Anti-patterns
- Inventing requirements that aren't in the issue.
- Treating an ambiguous feature as well-defined.
- Skipping straight to implementation choices.
